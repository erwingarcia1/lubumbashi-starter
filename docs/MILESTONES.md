## M2 — Tax engine
- [x] `lib/tax-engine`: pure functions. Given an entity's category and a date, produce the obligations due, with amount, period, due date, penalty (after N days, % or fixed), exemptions. Versioned rules by `effective_from`. 100% unit coverage including: rate change mid-year, partial payment allocation (oldest obligation first), penalty capping, exempt taxpayer, percentage-based rule.
- Demo: `pnpm test lib/tax-engine` shows the cases; a script prints obligations for the 5 seeded taxpayers.
- Built (2026-09-13): `lib/tax-engine/` pure functions: `periodsBetween`/`dueDateFor` (monthly, quarterly, annual; due day clamped), `applicableRules` (category ± overrides), `versionFor` (latest non-draft version in force on the period's first day; obligations keep it), `computeObligations` (registration period → asOf in Africa/Lubumbashi, exemptions, percent rules from `tax_base_fc`, skipped periods reported), `computePenalty` (grace, once/fixed/monthly simple, cap), `allocatePayment` (oldest first, principal before penalty, overpayment reported), `roundFc` (half up, D22). 100 % coverage enforced by `pnpm test:coverage` thresholds. `pnpm demo:obligations` prints the seeded entities' obligations and penalties.
- Demo (5 steps): 1. `pnpm test:coverage` → tax-engine lines at 100 % · 2. open `lib/tax-engine/engine.test.ts` and read the named cases (rate change mid-year, partial allocation oldest-first, penalty capping, exempt taxpayer, percentage rule, month-end boundary) · 3. `pnpm demo:obligations` · 4. compare taxpayer 125: June–September 5 000 FC each, August penalty 0 within the 30-day grace · 5. change a rule version's `effective_from` in Studio and rerun the script to see old periods keep their version.
- Not done: the seed still generates obligations with its own loop (identical results); M3 or M5 should replace it with `computeObligations` when obligations are issued at registration.
- Review notes: rounding rule D22 (`// DECISION-PENDING: D22`), penalties per rule version (not D2's single rule), monthly penalties simple not compounding, cap from `penalty_cap_bp`; liability start D27; boundary tests at 23:59 and 00:01 `Africa/Lubumbashi` on a month end.
